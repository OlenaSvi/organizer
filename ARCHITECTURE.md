# Архитектура «Организатора»

Документ описывает, **как устроено** приложение и **почему** именно так.
Обновляется вместе с кодом: меняется поведение — меняется этот файл.

Последнее обновление: 28 августа 2026.

---

## 1. Что это

Личный органайзер Елены. Одна HTML-страница, открывается двойным кликом,
работает без интернета и без сервера. Данные живут в браузере пользователя.

Пять экранов на одну и ту же жизнь: **Сегодня · Календарь · Карта · Матрица · Список**.

## 2. Устройство файлов

```
organizer/
├── Организатор.html      ← готовое приложение (собирается, не редактируется руками)
├── build.sh              ← сборка + проверка синтаксиса
├── src/                  ← ИСХОДНИКИ, правим только их
│   ├── app.head.part     стили, темы, дизайн-токены
│   ├── app.body.part     разметка каркаса, данные, миграции, базовая логика
│   ├── app.views.part    экраны: Сегодня, Календарь, Матрица, Список
│   ├── app.map.part      карта (SVG) и справочники в настройках
│   ├── app.modal.part    все окна: просмотр, правка, создание, настройки
│   └── app.events.part   обработчики, перетаскивание, render()
├── test/
│   ├── run.sh            прогон всех наборов
│   ├── harness.js        поддельный DOM (браузера в тестах нет)
│   ├── seed.js           общие помощники T.ok / T.reset / T.card
│   └── suites/*.js       наборы проверок
├── design/               дизайн-пакет и макеты
└── build/                временные файлы сборки (в git не идут)
```

**Порядок склейки важен:** `head → body → views → map → modal → events`.
Функции объявлены через `const`, поэтому вызывать их можно только после
объявления — миграции в `body` не должны опираться на `views`.

Сборка: `./build.sh` — склеивает части, вынимает JS и проверяет его
`new Function()`. Ошибка синтаксиса роняет сборку, а не приложение.

## 3. Данные

Всё состояние — один объект `S` в `localStorage["organizer.v1"]`.

```js
S = {
  items: [ … ],      // дела, рутины, встречи, идеи — одним списком
  spheres: [], places: [], people: [], types: [],
  cfg: { todayCap, urgentDays, weekStart, theme },
  open: [],          // раскрытые ветки карты
  hereNow: null,     // «Я сейчас: место»
  suggCollapsed: false,
  …флаги одноразовых миграций
}
```

Отдельным ключом `localStorage["organizer.view"]` хранится **где вы были**:
вкладка, ось карты, режим календаря, срез списка, порядок и период. Это про вид, а не про
данные, поэтому в выгрузку не попадает.

### Дело

```js
{ id, title, type, spheres: [], place, person,
  due, time, multi, steps: [{text, done}], options: [],
  routine: { days: [0..6], history: ["2026-08-27"] },
  mins, partOfDay,          // сколько занимает · утро / день / вечер
  repeat: { every, days: [0..6], day, month, history: [] },  // повтор встречи
  notes, forceImp, working, done, doneAt, created, createdAt,
  today, notToday }        // взято на день / отклонено в этот день
```

Ключевые решения:

- **Одно дело — одна запись.** Принадлежность нескольким сферам — это массив
  `spheres`, а не копии. Отметили сделанным — исчезло сразу отовсюду.
- **Два поля про создание, и оба нужны.** `created` — дата, по ней работает
  фильтр периода в «Списке» («за неделю», «за месяц»). `createdAt` — момент
  в миллисекундах, по нему сортировка «сначала новые»: без него все дела
  одного дня были неразличимы и внутри дня список раскладывался по алфавиту.
  Старым делам `createdAt` восстанавливает `normalizeItems()` по месту в
  массиве — новое дело всегда дописывалось в конец, поэтому порядок внутри
  дня выходит верным.
- **`type` — ссылка на справочник**, а не жёсткий список. Пользователь
  переименовывает и добавляет виды; поведение берётся из `kind`
  (`plain / choice / routine / appt / idea`).
  В стартовом наборе **пять** видов: дело, рутина, аппоинтмент, идея,
  напоминание. «Выбрать / купить» убрано — варианты решения
  пишутся и в заметке, а у идеи список вариантов остался; «сходить /
  съездить» тоже — это обычное дело, у которого просто заполнено место.
  Поведение `choice` из кода не удалено: у тех, кто завёл такой вид
  раньше, он продолжает работать.
  **Виды не правятся вовсе, и в настройках их нет.** Поведение зашито в
  код: «добавить вид» всё равно давало обычное дело — рутину заново им
  было не создать, то есть кнопка обещала больше, чем умела. Раз завести
  нечем, то и убирать нечего: остаться без рутины навсегда — ловушка, а
  не свобода. Справочник, в котором нечего делать, — лишняя дверь, и она
  закрыта. Вид у конкретного дела по-прежнему меняется в самом деле.
  В настройках остались три справочника: сферы, места, люди — это данные
  пользователя, а не поведение приложения.
- **Шаг помнит свой день.** У закрытого шага есть `doneAt`: он попадает в
  «сделанное» за сегодня, пока дело ещё живо, и считается в счётчике дня.
  Когда закрыт последний шаг, дело становится `done` целиком — и тогда
  показывается само дело, а его шаги в «сделанном» не дублируются.
- **`today` / `notToday` — даты, а не флаги.** Поэтому «взято сегодня» и
  «отклонено сегодня» самоочищаются при смене суток, без ночных заданий.

## 4. Правила, которые держат продукт

Это не украшения — на них опирается код, и ломать их нельзя молча.

### 4.1 Без вины
Ни красного цвета как сигнала опоздания, ни слова «просрочено», ни
восклицательных знаков. Прошедший срок выглядит так же спокойно, как
будущий: «22 августа · 6 дней назад».

Сюда же: штрихи дня сверх лимита ничем не выделены цветом. Раньше они
краснели — взять больше обычного не провинность, и краснеть тут нечему.
Где проходит лимит, видно по просвету перед первым лишним штрихом.

### 4.2 Отметка места прячет чужое — но не молча
`S.hereNow` — «я сейчас здесь». Дело, привязанное к другому месту, не
показывается **нигде**: держать его перед глазами нечестно, сделать его
отсюда всё равно нельзя. Чтобы увидеть всё сразу, в том же переключателе
есть «Везде · без учёта места».

Отсюда разделение: ракурсы берут дела через `here()` (= `live()` без
чужого места), а `live()` остаётся там, где речь о данных, а не о «что мне
делать»: счётчики мест в переключателе и в справочнике, поиск дубликатов,
выгрузка и архив. Счётчики специально считают всё — иначе непонятно, куда
уехали дела и где их искать. Архив тоже не фильтруется: сделанное — это
история, а не то, что можно сделать здесь.

Спрятанное всегда названо словами: `awayNote(n)` — одна формулировка на
все экраны. Молчаливое исчезновение дел выглядит как «переключатель не
работает» — или хуже, как потеря.

### 4.3 День складывается из трёх разных вещей
- **Встречи** — назначен час. В дне по факту, отменить нельзя.
  Отмеченная состоявшейся **остаётся в своей панели** зачёркнутой — как
  сделанное дело в колонке дел и отмеченная рутина в своей. Исчезнуть из
  панели и всплыть среди дел выглядело так, будто встреча куда-то делась.
  В счёт дня она не идёт: встреча не дело, и в лимит её никогда не
  считали.
- **Дела со сроком сегодня** (`dueTodayTask`) — назначен день. В дне
  тоже по факту: «сделать не позже сегодня» и «сделать сегодня» — одно
  и то же, выбирать нечего. Раньше они лежали в предложениях и их
  приходилось брать руками — лишнее решение на пустом месте.
  Отличие от встречи: убрать можно — встречу не отменишь, а срок ваш и
  двигается. Но убирание у них устроено иначе: взятое вручную просто
  теряет `today` и возвращается в «Предлагаю», а дело со сроком вернулось
  бы тем же путём, поэтому `unpickToday()` ставит ему `notToday` — сегодня
  не показываем, завтра придёт в предложения со своим прошедшим сроком.
  Подписи у кнопок разные и говорят именно это: «в предложения» у
  взятого, «не сегодня» у дела со сроком. Прошедший срок сюда **не** входит:
  там решение принимается заново, и тащить такое дело в день без спроса
  было бы упрёком.
- **Взятое вами** — ваш выбор из предложений.

`S.cfg.todayCap` ограничивает **только последнее**. Назначенное в лимит
не входит: его не выбирали, и «8 из 5» без выхода было бы упрёком, а не
реализмом. Когда назначенного вместе со взятым больше, чем помещается,
приложение спокойно говорит, из чего сложился день, и называет выход —
срок можно сдвинуть.

Счётчик «сделано N из M» считает всё в колонке дел: и назначенное
сроком, и взятое. Иначе сделанное дело со сроком выпадало бы из счёта.

### 4.4 Три состояния дела, а не два
`working` — «я этим занимаюсь». Не вид дела и не отдельная сущность, а
признак у обычного дела — как шаги. Решать заранее ничего не надо:
взялись за «искать няню» — включили, нашли — закрыли галочкой.

Зачем: у дела было ровно два состояния, и длинное дело месяцами висело в
первом. Отметишь галочкой — закроется, хотя няню не нашли. Не отметишь —
назавтра вернётся с пометкой **«не успели»**, будто провинились. А вы
занимались.

- **Кружок у названия** (`workDot`) — состояние показывается, а не
  подписывается: подпись спорила бы с метками сферы и срока. У дела с
  шагами карточка дня ведёт шагом, а не названием, — кружок стоит и там:
  «в работе» это про дело целиком, а не про его заголовок.
- **Кнопка «Взяться» / «Отложить»** устроена как «Сделать сегодня»:
  залитая зовёт, ссылка отменяет. Действия равнозначны, и выглядят
  одинаково.
- **Возвращается молча**: `whyCarried` не пишет «не успели» тому, кто в
  работе.
- **«В работе» не значит «сделано» нигде** — ни в счёте дня, ни в
  архиве. Галочка по-прежнему закрывает дело.
- **Взялись — значит сегодня.** Дело само встаёт в день: «начинаю» и «не
  сегодня» вместе не держатся, поэтому «взяться» снимает прежний отказ
  (`notToday`). Без этого дело со сроком сегодня, от которого утром
  отказались, оставалось спрятанным и из дня, и из предложений: помечено
  работой, а нигде не видно. Правила те же, что у «Сделать сегодня»,
  включая лимит — в переполненный день спросит, что вытеснить, а не
  влезет тихо. Признак при этом ставится в любом случае: он про ваше
  решение, а не про место в дне.
- **«Отложить» из дня не убирает.** Перестать работать над делом и
  выкинуть его из дня — разные решения, и одна кнопка не должна
  принимать оба.

Кнопки нет у рутины, встречи, идеи и напоминания: их не «делают
понемногу».

### 4.5 Важность — всегда ваша, срочность — всегда из даты
`isImportant(it)` — ручное решение (по умолчанию важное). Спрашивается
при создании и меняется в редакторе или перетаскиванием в матрице.

`urgency(it)` — вычисляется из `due` и `cfg.urgentDays`, вручную не ставится:
срочно всё, до чего осталось `urgentDays` дней или меньше, включая
прошедшие сроки. Без даты дело не срочно никогда. Рутина срочна только
в свой день по расписанию.

Матрица: строки — срочность, столбцы — важность; перетаскивание меняет
только столбец. В окне дела то же положение написано словами
(`QUADS[quadrant(it)]` → «Срочное важное» и т. д.) — у рутин и идей
метки нет, они в матрицу не попадают.

У края прокрутки — мягкая тень, и появляется она ровно тогда, когда за
краем ещё что-то есть: без неё срез посреди карточки читался как поломка
вёрстки, а не как «прокрутите». Приём известный: две заливки цветом фона
прокручиваются вместе с содержимым (`local`) и в крайних положениях
закрывают собой тени, прибитые к самой клетке.

Клетка показывает **все** свои дела. Раньше список обрывался на восьмом
и снизу стояло «и ещё 12» — надпись, которая никуда не вела: остальные
дела из матрицы было не достать. Теперь длинный список прокручивается
внутри клетки.

**Потолок высоты стоит на клетке, а не на списке.** Список — колонка
`flex:1` и занимает всё, что осталось после заголовка и описания. Когда
потолок был на списке (жёсткие 340px), соседняя клетка растягивала строку
сетки, клетка вытягивалась за ней, а список обрывался заметно выше
собственного края: обрез посреди карточки, а под ним пустота. Потолок на
клетке нужен затем, чтобы одна переполненная клетка не растянула всю
строку матрицы.

В календаре по месяцам в день помещается три записи — там клетки
слишком малы для своей полосы прокрутки, поэтому «и ещё N» открывает
этот день целиком (`data-act="calday"`), а не молчит.

### 4.6 Ссылки в заметках живые, но текст остаётся текстом
`linkify(text)` в `app.views.part` превращает адреса в заметках и вариантах
в кликабельные ссылки — только в **просмотре**, не в форме правки.

Порядок операций критичен для безопасности: текст режется на куски и
каждый кусок экранируется **отдельно**, включая сам адрес и его `href`.
Соблазнительный обратный порядок (экранировать всё, потом искать адреса
регулярным выражением) дырявый: после экранирования кавычка становится
`&quot;`, и адрес «дотягивается» до неё, утаскивая разметку внутрь `href`.

Ловятся только `http://`, `https://` и `www.` — `javascript:` ссылкой не
станет никогда. Знаки препинания в конце (`.`, `,`, `)`) отрезаются от
адреса: это конец предложения, а не часть ссылки.

В карточках списка и в календаре заметка показывается кусочком и НЕ
линкуется: ссылка внутри кликабельной карточки — две разные цели в одной
зоне нажатия.

### 4.7 Рутина: сколько занимает и когда
У рутины есть `mins` (длительность) и `partOfDay` (`morning / day / evening`).
Оба необязательны — «не важно» полноправный ответ.

Часть дня — переключатель `.seg`, тот же, что у настроек дня. Выбрано
всегда ровно одно, и четвёртый вариант — **прочерк**, а не «не важно»:
словом он раздувал переключатель шире половины строки, и тот переставал
помещаться (`.modal{overflow-x:hidden}` обрезал бы молча). Смысл прочерка
держит подсказка при наведении.

По той же причине `.cfggrid` складывается в один столбец уже на 620px,
а не на 520: в узкой двухколоночной сетке переключатель снова не влезал.

Длительность выбирается из списка (`MINCHOICES`), а не набирается: одно
нажатие вместо ввода, и не бывает «пятнадцвть минут». Точность тут не
нужна — нужен порядок величины, чтобы понять, помещается ли утро в утро.

Панель «Рутина» группируется по частям дня **только если** часть дня
проставлена хоть у одной рутины; иначе плоский список, как раньше.
Суммы в заголовках групп и в шапке панели считаются по НЕсделанным —
это «сколько ещё осталось», и число честно тает за день.

**Статистика — за четыре недели** (`monthInfo`), а не серией подряд.
Серии сознательно не сделаны: сорванная серия обнуляет месяц работы за
один пропуск — ровно тот механизм вины, от которого уходит §4.1. Доля
выполнения не обнуляется никогда.

Клетки карты бывают пяти видов, и ни одна не прозрачна: «не по
расписанию», «ещё впереди» и «рутины тогда не было» рисуются одинаково
бледно. Прозрачными они быть не могут — у новой рутины три строки из
четырёх исчезали, и карта выглядела дырой посреди окна. Сегодняшняя
клетка обведена: в двадцати восьми одинаковых квадратах иначе не за что
зацепиться.

В знаменатель идут только прожитые дни и только с `created`: иначе новая
привычка сразу показывала бы провал за месяц, которого не было. Сделанное
вне расписания в долю не идёт, а называется отдельно — «+2 сверх
расписания». Раньше `weekInfo` считал его в `hit` и выдавал «2 из 1».

### 4.8 Встреча по расписанию
Сессия у психолога дважды в неделю не помещалась ни в один вид: рутина
теряет время и календарь, а встреча знает ровно одну дату.

У встречи (`kind: "appt"`) появилось поле `repeat`. Повтор бывает
**четырёх видов** (`every`):

| `every` | что задаётся | пример |
|---|---|---|
| `week` | `days` — дни недели | психолог: вт, чт |
| `month` | `day` — число | квартплата: 5-го |
| `quarter` | `day` — число, раз в 3 месяца | отчёт: 1-го |
| `year` | `day` и `month` | день рождения: 12 марта |

Квартал отсчитывается от месяца, в котором запись появилась (`created`).
Число длиннее месяца сдвигается на последний день: пропустить февраль у
«каждого 31-го» выглядело бы как поломка, а не как арифметика.
Записи из прежних версий знают только дни недели — `normalizeItems()`
проставляет им `every: "week"`.

Предупреждения «за N дней» сознательно нет: важные дни рождения помнятся
и так, а для остальных достаточно поздравить словами в сам день.
Поле **своё, а не `routine`**, хотя дни недели устроены одинаково: смысл
разный. Пропуск рутины не страшен — так задумано (§4.1). Пропуск встречи
страшен: там время, другой человек и договорённость. Поэтому у встречи
нет ни доли выполнения, ни тепловой карты — только дни, время и «сколько
раз состоялась».

Форма собирает поля **по ячейкам сетки**, а не одной простынёй в одной
ячейке: «Когда», «Вид дела», «В какие дни», «Время». Иначе всё «когда»
уезжало в левый столбец, а правый пустовал.

Строке «Дата и время» тоже отдана вся ширина: дата, часы и минуты
стоят в одну линию, и втроём в половину строки они не помещались —
кнопка даты сжималась до одной буквы, а мини-календарь (`.dd` шириной
от 230px) вылезал за левый край окна и обрезался.

**Плитки дней — одна разметка на все места** (`daysRowHTML`): форма
рутины, форма встречи и оба окна просмотра. Раньше это были четыре копии,
и одна успела разойтись — окно архива показывало неделю с воскресенья
вопреки настройке `weekStart`, да ещё и под другой подписью. Блоку дней
отдана **вся ширина строки**: семь плиток — самый широкий элемент формы,
в половине строки они сжимались вдвое против просмотра, и казалось, что
у рутины и у встречи дни разного вида. Сами дни лежат в разных полях
(`routine.days` и `repeat.days`), разбирается `schedDays()`.

Время набирается **двумя списками — часы и минуты** (`ddTimeHTML`), а не
родным `input[type=time]`. У родного поля своя высота, из-за чего оно не
вставало вровень с соседней датой, и свой выпадающий список, который
листается по минуте и выглядит чужим в этом окне. Один список на все
четверти суток был бы не лучше: 24 строки и 12 — короткие, а высота
совпадает с датой сама, потому что кнопка ровно та же `.ddbtn`.

Расписание и одна дата — **взаимоисключающие** ответы на «когда»:
`normalizeItems()` стирает `due` у повторяющейся встречи, иначе она стояла
бы и по расписанию, и в свою дату.

Повторяется **бессрочно**, пока её не удалят: срока окончания нет — так
решила Елена. Переносов («на этой неделе во вторник вместо четверга»)
тоже нет: это отдельная машинерия исключений. Обходной путь — разовая
встреча на новую дату.

**Галочка в календаре знает свой день.** У повторяющейся записи одной
даты нет — та же встреча стоит в десятке клеток, — и «отметить» без
указания дня отмечало сегодняшний: в прошлом четверге при этом не
менялось ничего, а кружок выглядел неработающим. Поэтому в календаре у
таких записей действие `toggleon` с датой клетки, а состоявшаяся в этот
день строка показана зачёркнутой. Будущие клетки галочки не имеют вовсе:
«состоялась» про завтра — бессмыслица.

Галочка отмечает **день**, а не закрывает запись: `toggleDone` пишет в
`repeat.history`, как у рутины. Отсюда два следствия: строка в панели
обязана выглядеть отмеченной (`.aline.done`) — разовая встреча после
галочки исчезает сама, а повторяющаяся остаётся, и без метки казалось бы,
что нажатие не сработало; и прошедшие сессии попадают в архив через
`doneEntries()` с флагом `byDay` — вернуть можно только сегодняшнюю,
потому что галочка работает с сегодняшним днём.

### 4.9 Напоминание — не дело
`kind: "remind"`. Его не делают, про него помнят: день рождения, посылка
в пути, «привезут машину в среду». Отсюда всё поведение:

- **не предлагается** и не входит в лимит дня — напоминание нельзя не
  успеть;
- **нет важности и срочности**, в матрицу не идёт: к посылке эти слова
  неприменимы;
- **нет времени**, только день — «привезут в среду», а не в 14:30;
- живёт в панели **«События дня»** вместе со встречами: смысл общий —
  «что сегодня происходит», а не «что я делаю». Панель поэтому и
  переименована из «Аппоинтментов»;
- повторяется тем же механизмом, что и встреча (§4.7), всеми четырьмя
  способами: годовой — это про дни рождения.

Отметка означает «было», а не «сделано»: запись остаётся в панели
зачёркнутой, как состоявшаяся встреча.

Ожидание («должны ответить», «посылка в пути») отдельным видом не
сделано намеренно: от «помнить» оно отличается только вашей реакцией, а
не поведением приложения. Прошёл день — напоминание осталось с
прошедшей датой, как дело с прошедшим сроком.

### 4.10 Один словарь дат
`dateLabel(it)` — единственное место, где дата превращается в слова.
Все экраны зовут его; вторых формулировок в коде быть не должно.

### 4.11 Ничего не пропадает молча
Если что-то не показано — приложение объясняет словами, почему
(`whyRest`, `whyEmpty`, счётчик спрятанного при выбранном месте).

## 5. Как собираются предложения

`todayItems()` в `app.views.part` — сердце экрана «Сегодня».

**Кандидаты:** живые дела, кроме рутин, встреч и идей; доступные из
текущего места (`reachable`); не взятые и не отклонённые сегодня; и **не
со сроком сегодня** — такие уже в дне (§4.3).

**Три повода предложить дело, и больше никаких:**
1. **не успели** — брали в прошлые дни и не закрыли. Любое, в том числе
   неважное: это уже был ваш выбор;
2. **скоро срок** — важное, до срока осталось не больше `urgentDays`;
3. **давно ждёт** — важное вообще без срока. Именно оно не делается
   годами, потому что его ничего не подпирает.

Всё остальное молчит и придёт само в свой день.

**Одна бронь:** место под «давно ждёт» держится всегда — без дедлайна оно
вечно в хвосте и иначе не показалось бы никогда. Остальное ждёт в очереди,
и её размер написан под списком.

Раньше поводов было четыре, множества пересекались, а два места из семи
держались за «неважным со сроком». Эта бронь существовала ровно затем,
чтобы дело с сегодняшним сроком не исчезло из дня. Теперь оно попадает
туда само, и вся ветка стала не нужна: сборка предложений похудела
вдвое.

### 5.1 Экран «Список»

Три независимых регулятора: **срез** (что показывать — все, вид,
с шагами, сделанные, срок прошёл), **период** и **порядок**.

Срезы по видам строятся из справочника, а отдельного среза «дела» больше
нет: он значил «всё, кроме рутины, встреч и идей», а плоский вид остался
один и называется «дело» — два соседних пункта означали одно и то же.
Виды не заводятся (§3), так что второй плоский вид не появится.

Рутина отмечается и из «Списка» — тем же днём, что и в панели дня.
Раньше там стояла приглушённая заглушка: кружок нарисован, нажимаешь —
ничего. Либо кнопка работает, либо её нет; выбрано первое, потому что
отметить рутину, просматривая список, — обычное желание.

**Рутины в архиве нет.** Она отмечается каждый день, и за месяц это
сотня записей, под которыми тонет всё настоящее. Её история видна в ней
самой — недельные точки и карта четырёх недель (§4.6). Архив отвечает
«что я сделала», а не «сколько раз я почистила зубы». В панели дня
отмеченная рутина при этом остаётся на виду: там не история, а состояние
сегодня, и без метки галочка выглядела бы впустую.

Повторяющаяся встреча в архив **попадает**: сессия у психолога — событие,
а не привычка, и «состоялась 23 августа» это настоящая история.

Период отвечает на разные вопросы в разных срезах и потому считается по
разным датам: в архиве «сделанные» — по дате выполнения («что я сделала
за неделю»), в живых срезах — по дате появления дела («что я записала»).
По умолчанию «за всё время»: список ничего не прячет, пока вы сами не
попросите.

## 6. Отрисовка

Один цикл: `render()` в `app.events.part`.

```
render()
 ├ normalizeItems()   самопочинка данных (см. §7)
 ├ saveView()         запоминаем, где мы
 ├ renderChrome()     шапка: вкладки, дата, «Я сейчас», «Разобрать»
 └ renderToday | renderCalendar | renderMap | renderMatrix | renderAll
```

Экран перерисовывается целиком. Прокрутка страницы и колонок «Сегодня»
восстанавливается после перерисовки, чтобы список не прыгал.

**Прокрутка на «Сегодня»:** страница не прокручивается, экран равен высоте
окна. Заголовки панелей («Дела», «Рутина», «Аппоинтменты») неподвижны, а
прокручивается только содержимое под ними — `.tscroll` в левой колонке и
`.panelscroll` в панелях правой. Рутина забирает свободную высоту, встречи
держат свою (до 46% колонки) и тоже получают прокрутку, если их много.
На узком окне всё складывается в столбик и прокрутка снова страничная.

**События — делегированием.** Один слушатель на `document`, действия
объявляются атрибутом `data-act` в разметке. Никаких `onclick`.

**Окна** живут в `#modalHost`, празднование — в `#cheerHost`.

**Справочники правятся черновиком** — сферы, места и люди (см. §3). При входе на второй уровень
настроек делается снимок (`dirBackup`): переименования, добавления и
удаления сразу видны в списке, но закрепляются только кнопкой
«Сохранить изменения» — она же показывает слева «Изменения сохранены»
и оставляет окно открытым. Крестик возвращает снимок целиком, включая
метки на делах. Переход «‹ Настройки» — обычная навигация: сделанное
остаётся. Добавление — по Enter, отдельной кнопки нет.

**Футер окна закреплён.** Ряд кнопок помечается классом `row modalfoot`
и прилипает к низу (`position: sticky`): длинную форму можно листать, а
«Готово», «Добавить» и «Применить изменения» остаются на виду.
Отрицательные отступы гасят внутреннее поле окна, чтобы полоса шла от
края до края. Набор `09-modal-footer.js` следит, чтобы футер был ровно
один в каждом окне и действия из него работали.

**Форма дела одна на два окна.** `itemFormHTML(it, ids)` в `app.modal.part`
рисует поля и для создания, и для правки.

**Порядок полей один на все виды дел:** «Вид дела» → «когда» (у каждого
вида своё) → сфера → место и человек → важность → шаги, заметка, варианты.
Сначала «что это», потом характеристики. Раньше «Вид дела» оказывался то
вторым, то четвёртым — в зависимости от вида, и форма каждый раз выглядела
по-новому. Набор `17-form-order.js` сверяет полную последовательность
подписей для каждого вида.

Ячейки сетки строит один помощник `cell(label, body, wide)`. `wide` даёт
классу `.cfgitem.wide` — классом, а не инлайновым `grid-column`, потому
что по нему же правится раскрытие списка: у широкого поля список
раскрывается от **левого** края (`left:0`), иначе прижатый вправо он висел
посреди широкой кнопки и выглядел съехавшим. Широкая ячейка занимает
строку целиком — и когда поле иначе не помещается (дни недели,
дата со временем), и когда полей нечётное число: иначе рядом с последним
зияла бы пустая клетка. Тот же набор проверяет, что половинных ячеек
всегда чётное число.

Соседи в строке одной высоты: `.seg` внутри `.cfgitem` подогнан под 44px
`.ddbtn` (сам по себе он 38px), иначе строка «Вид дела · Когда» читалась
как разъехавшаяся.

Расстояния держит сетка (`gap` и `margin-bottom` у `.cfggrid`), а не
собственные отступы полей: раньше каждое поле добавляло свой
`margin-bottom`, и ритм формы плыл от вида к виду. Различаются
только заголовок, идентификаторы полей и кнопки внизу. До этого формы
были написаны дважды и успели разъехаться по составу и порядку секций —
набор `08-form-parity.js` сравнивает их посекционно и не даёт повториться.
Закрытие только по крестику: клик по фону и Escape намеренно ничего не
делают (просьба Елены — случайные закрытия теряли начатое).

## 7. Самопочинка данных

`normalizeItems()` вызывается при загрузке и перед каждой отрисовкой.
Все действия идемпотентны.

- у идей и рутин стирается забытый `due` — иначе они висят в календаре;
- у всего, что не встреча, стираются `time` и `repeat`. Сменили вид с
  аппоинтмента на дело — время оставалось в записи и всплывало в
  подписях («5 ноября 10:00»), хотя поля для него в форме нет; а
  расписание повторов уводило галочку в историю повторов вместо того,
  чтобы закрыть дело. Смена вида чистит их сразу, самопочинка — те
  записи, что уже успели испортиться;
- прошедшая встреча наутро уходит в архив как «состоялась» своим днём;
  флаг `autoDone` не даёт утащить её обратно, если вы нажали «вернуть»;
- `today` в будущем стирается — остаток удалённой кнопки «завтра».

**Миграции** — одноразовые блоки в `app.body.part`, каждый под своим флагом
(`reset2026_08`, `apptTodayExample`, `itemsCleared`, …).

Переименование `task` в «дело» (31 августа 2026) меняет **только
подпись** и только если она ещё стандартная: переименовал человек сам —
его слово важнее. Ключ вида прежний, поэтому ни одна запись не тронута.

**Порядок критичен, и он двусторонний:**
- блоки, которые *создают* образцы, идут после сброса `reset2026_08` —
  иначе он сотрёт их работу;
- блок `itemsCleared` (полная очистка дел, 28 августа 2026) стоит **последним**
  среди всех создающих — иначе они досоздали бы дела уже после очистки.
  Эта ошибка была допущена и поймана тестом при первой попытке.

**Разовые правки не касаются первого запуска.** `seed()` создаёт новое
состояние сразу со всеми флагами `true`. Правка чинит историю уже
заведённого приложения; тому, кто открыл его впервые, чинить нечего.
Без этого очистка дел, сделанная однажды для своих данных, стирала
примеры и у любого нового человека — приложение открывалось пятью
пустыми экранами, и показать его было нечего. Набор `06-first-run.js`
следит, чтобы у новичка были примеры всех видов дел.

Справочники, настройки и виды дел очистка не трогает — они переживают
любое обнуление дел.

## 9. Тесты

Браузера в среде нет, поэтому в `test/harness.js` — поддельный DOM:
`document`, `window`, `localStorage`, делегированный `clickOn({act, id, …})`.
Прогон: **JavaScriptCore** через `osascript -l JavaScript`.

```bash
./test/run.sh          # все наборы
./test/run.sh today    # только про «Сегодня»
```

Набор считается пройденным, если печатает «проблем не найдено».

**Тесты не зависят от данных приложения.** `T.seed()` в `test/seed.js`
создаёт свой предсказуемый набор дел (обычные, многоэтапное, две рутины,
встреча, идея). Поэтому очистка или смена шаблонов не ломает проверки —
кроме `06-first-run.js`, который как раз проверяет первый запуск.

**Чего харнесс не умеет** (и о чём нельзя делать выводы из тестов):
реальные размеры, переносы текста, наведение мыши, настоящие события
браузера. Всё, что про вид, проверяется глазами на скриншотах.

**Правило после каждой правки:** сначала проверка, потом код —
и `./test/run.sh` перед коммитом.

## 10. Известные ограничения

- Данные живут в одном браузере. Перенос — только через «Сохранить в файл».
  Синхронизации между устройствами нет.
- Вёрстка рассчитана на компьютер и айпад. На узком экране колонки
  складываются, но телефонной раскладки как таковой нет.
- Ширина текста на карте оценивается по числу символов — точных замеров
  в SVG без браузера не сделать.

**Раскладка карты — дерево влево-вправо, не круг.** Корень посередине,
ветки расходятся в обе стороны и складываются столбиком. Круг упирался
сам в себя: десять дел в ветке раздвигали соседей по окружности, и карта
расползалась вширь. У дерева много дел — это просто длиннее столбец.
Стороны набираются по очереди: следующая ветка ложится туда, где пока
ниже, иначе один бок свисает намного дальше другого.

**Одна конструкция на обоих уровнях.** И от корня к веткам, и от ветки к
делам идёт одна и та же гребёнка: ствол до общей стойки, стойка вдоль
неё, от стойки отвод к каждому. К веткам она сплошная, к делам —
пунктирная: так видно, где ствол, а где веточка.

**Ветка — плашка с заливкой и белой подписью**, число дел в скобках.
Дело — просто тёмный текст на конце пунктира; прозрачный прямоугольник
под ним нужен только чтобы было куда нажать и за что взяться. Корень —
такая же плашка, только квадратная и того же радиуса углов; цвет вне
восьмёрки сфер, иначе он читался бы девятой сферой.

**Ширина подписи меряется настоящим шрифтом** (`textW`) — через холст,
если он есть, и по числу знаков в проверках, где холста нет. Раскладка
держится на этих числах, поэтому способ должен быть один и тот же в
обоих счётах: при замере места под ветку и при отрисовке.

**Разворот на весь экран** (`MAPFULL`) — обёртка `.mapstage` встаёт
`position:fixed` поверх страницы, оси и кнопки едут вместе с ней: иначе
ими не воспользоваться. Сама карта не меняется — ей просто отдают всё
окно, масштаб и сдвиг остаются как были.

Состояние нарочно **не запоминается**: снимается в `render()` при любом
уходе с карты и не пишется в `organizer.view`. Иначе, вернувшись через
день, находишь карту на весь экран и не понимаешь, что случилось. Снятие
живёт в `render()`, а не в обработчике вкладки, потому что уйти с карты
можно и иначе — например восстановлением вида при загрузке.

**Перетаскивания дел по карте нет.** Оно читалось как основное действие —
дело ездило за пальцем от любого движения, — а нужно было редко: сменить
сферу проще в самом деле. Вместе с ним ушли список целей для броска,
подсветка ветки и пересчёт экранной точки в координаты карты.

Сама карта по-прежнему двигается перетаскиванием, а лист открывается
обычным делегированным нажатием — как всё остальное в приложении.
Отдельный путь «карта сама ловит нажатие» был нужен только потому, что
тот же жест мог оказаться переносом.

Проверка на ноль пересечений при всех раскрытых ветках осталась и
сторожит раскладку по-прежнему.
